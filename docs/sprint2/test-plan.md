# План тестування продукту «ЕдуПортал» (Test Plan)

**Продукт:** П6 «ЕдуПортал» (`eduportal`)  
**Версія вимог:** SRS v1.1  
**Середовище:** Moodle Sandbox (`https://sandbox.moodledemo.net`) та модуль Java `ua.kpi.tzyapz.eduportal` (v1.0.0)  
**Автор:** С. Керничний (Інженер з тестування)  

---

## 1. Межі тестування (Scope)

* **Що тестується:**
  1. Модуль бізнес-логіки Java (`GradeCalculator`, `QuizScorer`, `EnrollmentValidator`) на відповідність вимогам `BL-10`...`BL-80`.
  2. Веб-інтерфейс LMS Moodle Sandbox для ролей `student`, `teacher`, `manager`, `admin` (функції `F-10`...`F-140`, `GUI-10`...`GUI-90`).
  3. Обчислення підсумкового балу, штрафів за запізнення, шкали ECTS та валідація кодового слова самозарахування.
  4. Нефункціональні вимоги `P-10`, `S-10`, `S-20`, `U-10`, `U-20`, `D-10`, `D-20` (з обмеженнями, описаними в п. 2.2 і п. 3).
* **Що НЕ тестується:**
  1. Фізична безпека серверів Moodle Demo HQ та налаштування баз даних PostgreSQL/Redis (зокрема внутрішнє зберігання хешів паролів із `S-10`, яке недоступне ззовні).
  2. Відправка реальних e-mail повідомлень (обмеження демо-стенду `sandbox.moodledemo.net`): `F-20` та підтвердження адреси в `F-110` перевіряються до моменту відправлення листа.
  3. Зовнішні плагіни відеоконференцій та сторонні сервіси.

## 3. Ризики та припущення

* **Головний ризик:** щогодинне скидання даних на демо-стенді `sandbox.moodledemo.net`.
* **Заходи пом'якшення:** усі тест-кейси є незалежними; створення курсів та елементів оцінювання автоматизується або виконується на початку години з фіксацією часу у журналі. Альфа- та бета-сеанси тривають не довше години.
* **Ризик:** стенд спільний і сторонній, тому навантажувальні перевірки на ньому неможливі, а тест блокування облікового запису може на час закрити доступ іншим. Заходи: повна перевірка `P-10` лише на власному екземплярі; тест `S-20` на окремому обліковому записі наприкінці години.
